# 기록 공개·개인정보 원칙

- 기록 유형: 기준 · 생산자: 클로이 · 근거: 저장소 규칙(AGENTS.md: 실제 운영 데이터·자격증명 미커밋), 2026-11-14·16 회의록 작성 시 적용한 기준
- 상태: 확정 · 최종 확인일: 2026-11-17

## 저장소에 넣지 않는 것

| 종류 | 예 | 보관 위치 |
|---|---|---|
| 지원자·면접자 개인정보 | 이름, 나이, 성별, 연락처, 거주지 | 원드라이브(비공개) |
| 제3자 신상 | 정보공개청구 청구인의 이름·생년월일·주소·연락처 | 원드라이브(비공개) |
| 대표 개인 신용·채무 | 보증 심사, 연체, 채무 정리 내역 | 원드라이브(비공개) |
| 고객 실데이터 | 이용자 명단, 전화번호, 동의서 작성본 | 운영 시스템(접근 통제) |
| 자격증명 | 비밀번호, API 키, 인증서 | 저장소 밖 |

저장소에는 대신 "무엇이 어디에 있는지"만 적는다(`90_색인/등록대장.md`).

## 문서에 적을 때

- 채용 결과는 "면접 지원자 1명 불합격 통보"처럼 사람을 특정하지 않는다.
- 직원은 업무상 필요한 이름·직책만 적는다(예: 임주형 CSO).
- 공무원은 업무 연락처(부서·대표번호)만 적는다.
- 고객 대상 자료 수집은 거주 시·군 단위처럼 최소한으로 하고, 대외 제공은 집계 자료만 한다.

## 표현 원칙

- 토요플레이는 고객·홍보물에 '보육' 표현을 쓰지 않는다. 군 정책 문서에서는 "주말 아동 체험 프로그램", "돌봄 부담 완화" 등 정책 언어를 쓸 수 있다.
- 확정되지 않은 값은 빨간 `[ ]`로 비워 두고 임의 값을 넣지 않는다.
- 실행하지 않은 검증·확인은 완료로 적지 않는다.
