# BEN-015 JEV 상담 1차 구현 — 운영 활성화 전 검증 필요

2026-10-05. 공개 홈페이지의 문의 → 규칙 검사 → JEV 의도 선택 → 승인 답변 선택 → 전화 문의 안내 구조다. 자유 생성 문장을 고객에게 전달하지 않는다. JEV는 실제 TypeSafe HTTP 계약으로 연결하되 키 없는 개발 환경에서는 기본 안내 모드다. 운영 24시간 가용성/SLA를 검증하거나 보장한 상태가 아니다.

## 공식 계약 근거

- https://docs.typesafe.ai/introduction/quickstart
- https://docs.typesafe.ai/primitives/choice
- https://docs.typesafe.ai/confidence

2026-10-04 열람. POST https://api.typesafe.ai/v1/systemone, state/model/questions 입력과 answers.intent.choice/confidence/probabilities 출력을 검증한다. confidence와 선택 확률은 별개로 검사한다. 0.65/0.75는 잠정 개발 임계값이며 한국어 실측 평가 후 조정해야 한다.

## 서버 설정 (값은 저장소/브라우저/채팅에 넣지 않음)

- TYPESAFE_API_KEY: 서버 환경변수에만 설정
- JEV_MODEL: 계정에서 지원하는 모델 ID를 명시
- JEV_ENABLED: 기본 미설정. true일 때만 유료 외부 호출 가능

키를 넣기 전에도 모의 시험이 가능하다. 운영 활성화 전 요청 제한·일별 호출 상한·공급자 지출 한도와 차단 스위치를 구성해야 한다. 현재 코드의 입력 제한/타임아웃/중복 전송 억제는 분산 과금 방어가 아니다. Origin도 인증/비용 차단이 아니다. 해당 작업 전 JEV_ENABLED=true로 공개 배포하지 않는다. 유료 호출·계정 가입·키 발급은 이번 작업에서 실행하지 않았다.

## 기능/개인정보 경계

요금·시간·위치·시설·예약·단체의 고정 답변만 제공한다. 환불/사고/개별처리는 전화 안내이며 직원 접수·예약·결제·자동 문자 발송을 하지 않는다. 브라우저 대화는 메모리에만 두고 최근20개 문단만 표시한다. 앱은 질문을 DB/콘솔에 기록하지 않는다. 공급자/호스팅의 로그·보존 정책은 별도 확인 필요.

전화·이메일·주민번호 형태는 외부 전송 전 차단하나 이름·주소 등 모든 개인정보를 탐지하는 보장은 없다. 화면에 입력 주의 및 TypeSafe 전송 가능성을 알린다. 운영 DB, 원본 Drive, 직원 기록에는 접근하지 않는다.

답변은 BEN-014 고객 홈페이지와 대표 결정의 공개 정보 스냅샷이다. 05/site_profile.json 가격 승격은 아직 별개이므로 이 구현으로 confirmed를 자동 변경하지 않는다. 다음 단계에서 클로이가 출처/버전/고객 고지 일치 검사를 담당한다. 현재 간단 규칙은 한국어 표현 전체를 이해하지 못하고 다중 문의는 재질문한다. JEV가 잘못 분류할 가능성도 있으므로 라이브 한국어 평가가 필요하다.
