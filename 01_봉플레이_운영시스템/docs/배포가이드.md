## 배포 순서

### 1단계 — Supabase 먼저 (필수)

`설정가이드.md`를 따라 진행하십시오. **DB를 먼저 만들어야 3개 기기 동기화가 됩니다.**
`supabase_setup.sql`을 SQL Editor에서 실행하고, **Project URL**과 **anon public key**를 복사해두십시오.

### 2단계 — config.js 채우기

`assets/config.js`를 열어 두 줄을 채웁니다.

```javascript
SUPABASE_URL: 'https://xxxxx.supabase.co',
SUPABASE_ANON_KEY: 'eyJhbGciOiJIUzI1NiIs...',
```

**여기에 넣어두면 각 기기에서 따로 입력할 필요가 없습니다.**

접근 제한을 걸고 싶으면 `ACCESS_CODE`도 채우십시오. 비워두면 URL을 아는 누구나 들어옵니다.

### 3단계 — Netlify 업로드

**가장 쉬운 방법 (드래그앤드롭)**

1. https://app.netlify.com/drop 접속
2. 이 폴더를 통째로 드래그해서 놓기
3. 끝. 몇 초 뒤 `random-name-123.netlify.app` 주소가 생깁니다

**주소 바꾸기**: Site configuration → Change site name → 예: `bongplay`
→ `https://bongplay.netlify.app`

**업데이트할 때**: 같은 페이지에 다시 드래그하면 덮어씁니다.

### 4단계 — 각 기기에서 접속

3개 기기(매표소·사무실·현장)에서 주소를 열고, **홈 화면에 추가**하면 앱처럼 씁니다.

- **iPhone/iPad**: 사파리 → 공유 → 홈 화면에 추가
- **Android**: 크롬 → 메뉴 → 홈 화면에 추가

각 기기에서 한 번은 **DB 설정 → 이 기기의 위치**(매표소/사무실/현장)를 지정하십시오.
어느 기기에서 입력했는지 추적됩니다.

## 짧은 주소

`_redirects` 덕분에 아래처럼 짧게 접속할 수 있습니다.

| 주소 | 화면 |
|---|---|
| `/` | 메인 허브 |
| `/emergency` | 비상대응 |
| `/operations` | 현장운영 |
| `/management` | 운영관리 |
| `/consent` | 안전동의서 |
| `/forms` | 서식 모음 |
| `/incident` | 사고보고서 |

**매표소 태블릿은 `/consent`를, 현장 폰은 `/emergency`를 홈 화면에 추가**해두면 편합니다.

## 인쇄 / PDF 저장

모든 화면 우측 하단에 **인쇄 버튼**이 있습니다. 누르면 대화상자가 뜨고,
대상을 **"PDF로 저장"**으로 바꾸면 파일로 남습니다.

인쇄물은 자동으로 정리됩니다.

- 화면의 어두운 배경 → **흰 종이에 검은 글씨**
- 버튼·메뉴·모달 → 인쇄에서 제외
- 상단에 사업장명·주소가 머리글로 들어감
- 탭으로 가려진 내용은 인쇄되지 않음 (보고 있는 화면만 나옴)

**서식(`/forms`)은 클릭해서 채운 뒤 인쇄**하시면 됩니다.
안 채운 칸은 점선 빈칸으로 나가 손으로 적을 수 있습니다.

## ⚠ 보안 주의

`config.js`의 anon key는 **브라우저에서 그대로 보입니다.**

- Supabase의 RLS(행 수준 보안)로 보호되지만, 완전하지 않습니다
- **고객이 직접 만지는 기기**에는 민감 데이터 화면을 열어두지 마십시오
- 더 강한 보호가 필요하면 **Netlify Password Protection**(유료) 또는 Netlify Identity를 검토하십시오

### 개인정보 관련

`consent.html`에서 수집하는 보호자 성명·연락처·자녀 정보·서명은 **3년 보관 후 파기**한다고 동의서에 명시되어 있습니다.
`supabase_setup.sql` 하단의 파기 쿼리를 연 1회 실행하거나 Cron에 등록하십시오.

## 오프라인 동작

봉화 산간지역 특성상 네트워크가 끊길 수 있습니다.

- **입력은 항상 기기에 먼저 저장**되므로 오프라인이어도 매표·동의서·점검이 정상 작동합니다
- 네트워크 복구 시 **자동으로 클라우드에 올라갑니다** (2분마다 재시도)
- 헤더 배지가 노란색 "동기화 대기 N"이면 아직 안 올라간 게 있다는 뜻입니다

단, **처음 접속할 때는 인터넷이 필요합니다** (Tailwind·Lucide를 CDN에서 받기 때문).
한 번 열어두면 이후 오프라인에서도 대체로 동작합니다.

## 문제가 생기면

| 증상 | 확인 |
|---|---|
| 페이지가 안 열림 | 폴더 통째로 올렸는지 (index.html이 최상위에 있어야 함) |
| DB 미연동으로 뜸 | `config.js`의 URL/키가 비어 있거나 오타 |
| "테이블이 없습니다" | `supabase_setup.sql`을 실행하지 않음 |
| 아이콘이 안 보임 | 인터넷 연결 확인 (CDN 필요) |
| 수정했는데 반영이 안 됨 | 브라우저 강력 새로고침 (Ctrl+Shift+R) |
