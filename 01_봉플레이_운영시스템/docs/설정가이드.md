# 봉플레이 운영시스템 — 클라우드 DB 설정 가이드

매표소 · 사무실 · 현장 3개 기기가 같은 데이터를 보도록 연결하는 절차입니다.
**10분 정도 걸리며, 최초 1회만 하면 됩니다.**

---

## 1단계 — Supabase 계정 만들기

1. https://supabase.com 접속 → **Start your project** → GitHub 또는 이메일로 가입
2. **New project** 클릭
   - Name: `bongplay`
   - Database Password: 아무거나 (적어두십시오, 나중에 필요할 수 있습니다)
   - Region: **Northeast Asia (Seoul)** ← 반드시 서울로 선택 (속도 차이 큼)
3. 생성까지 1~2분 대기

**비용**: 무료 플랜으로 충분합니다. 봉플레이 규모(연 2만 명)에서는 무료 한도(500MB)를 넘기 어렵습니다.

---

## 2단계 — 테이블 만들기

1. 좌측 메뉴 → **SQL Editor** → **New query**
2. 첨부된 **`supabase_setup.sql`** 파일 내용을 전부 복사해 붙여넣기
3. 우측 하단 **Run** 클릭
4. "Success. No rows returned" 나오면 성공

---

## 3단계 — 접속 정보 확인

1. 좌측 메뉴 → **Project Settings**(톱니바퀴) → **API**
2. 두 가지를 복사해두십시오.
   - **Project URL**: `https://xxxxx.supabase.co`
   - **anon public** 키: `eyJhbGci...` 로 시작하는 긴 문자열

> ⚠ **service_role 키는 절대 쓰지 마십시오.** 반드시 `anon public` 쪽입니다.

---

## 4단계 — 각 기기에 입력

**3개 기기에서 각각 반복합니다.**

1. `봉플레이_총괄_마스터_대시보드.html` 열기
2. 우측 상단 **DB 미연동** 버튼 클릭
3. 입력:
   - **이 기기의 위치**: 매표소 / 사무실 / 현장 중 선택 ← 기기마다 다르게
   - **Project URL**: 3단계에서 복사한 URL
   - **anon public key**: 3단계에서 복사한 키
4. **연결 테스트** → "✓ 연결 성공" 확인
5. **저장**

버튼이 **"DB 동기화 정상 · 매표소"** 처럼 초록색으로 바뀌면 완료입니다.

---

## 작동 방식 — 알아두실 것

### 오프라인이어도 멈추지 않습니다
봉화 산간지역 특성을 고려해, **입력은 항상 기기에 먼저 저장**됩니다.
네트워크가 끊기면 대기열에 쌓아두었다가, **복구되면 자동으로 클라우드에 올립니다.**
헤더 버튼이 노란색 "동기화 대기 3"으로 바뀌면 아직 안 올라간 게 있다는 뜻입니다.

### 어떤 데이터가 동기화되나

| 화면 | 저장되는 곳 |
|---|---|
| 현장운영 대시보드 (매출 입력) | `sales_records` |
| 모바일 안전동의서 | `safety_consents` |
| 일일 안전점검 일지 | `safety_audits` |
| 교대근무·마감정산 | `closing_records` |

### CSV 백업
DB 설정 창 좌측 하단 **CSV 백업** 버튼을 누르면 로컬 데이터가 엑셀 파일로 떨어집니다.
**월 1회 정도 받아두시길 권합니다.** 클라우드가 있어도 별도 백업은 필요합니다.

---

## ⚠ 보안 주의사항

**anon key는 브라우저에 저장되고, 개발자도구로 볼 수 있습니다.**

- ✅ 매표소·사무실·현장 등 **내부 직원만 쓰는 기기**에는 입력해도 됩니다
- ❌ **고객이 만지는 태블릿에는 입력하지 마십시오** (안전동의서를 고객이 직접 작성하는 기기 등)

고객용 기기는 DB 연동 없이 로컬 저장만 쓰다가, 직원이 주기적으로 동기화하는 방식이 안전합니다.

---

## 개인정보 관리 — 반드시 확인

`safety_consents` 테이블에는 **보호자 성명·연락처·자녀 정보·서명 이미지**가 저장됩니다.

- 동의서에 명시한 **보관기간 3년**이 지나면 파기해야 합니다
- `supabase_setup.sql` 하단에 파기용 쿼리가 주석으로 들어 있습니다
- Supabase → Database → **Cron**에 등록하거나, 연 1회 수동 실행하십시오

```sql
delete from safety_consents where created_date < (current_date - interval '3 years');
```

---

## 문제가 생기면

| 증상 | 원인 / 해결 |
|---|---|
| "테이블이 없습니다" | 2단계 SQL을 실행하지 않았습니다 |
| "API 키가 올바르지 않습니다" | `service_role` 키를 넣었을 가능성. `anon public`으로 교체 |
| "네트워크 오류" | URL 끝에 `/`가 붙었거나 오타. 다시 복사해 붙여넣기 |
| 계속 "동기화 대기"만 쌓임 | 연결 테스트를 다시 해보십시오 |
