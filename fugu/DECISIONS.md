# 결정 기록

## D-001 — Fugu를 영속 기억 공간으로 사용

- 날짜: 2026-09-18
- 결정: 대화 기억 대신 `C:\Users\bongp\fugu`의 문서·스냅샷·로그를 인수인계 기준으로 사용한다.
- 이유: Ctrl+C, 컴퓨터 종료, 세션 전환 후에도 남아야 하며, 매번 프로젝트 전체를 다시 읽지 않아야 한다.

## D-002 — 증거 우선 판정

- 날짜: 2026-09-18
- 결정: 파일·라인 또는 실행 결과가 없는 "동작한다" 주장은 미검증으로 둔다.
- 이유: 주석과 UI가 실제 연결되지 않은 사례가 확인되었다.

## D-003 — Fugu와 프로젝트 배포 산출물 분리

- 날짜: 2026-09-18
- 결정: Fugu의 기억·스크립트는 프로젝트 배포 ZIP에 넣지 않는다.
- 이유: 기억 문서, 내부 감사, 작업 경로, 비밀 위치가 웹에 노출되면 안 된다.

## D-004 — 외부 상태와 로컬 코드 상태 분리

- 날짜: 2026-09-18
- 결정: 로컬 SQL 정의는 "실제 DB 적용 완료"를 의미하지 않는다. 외부 서비스는 미검증으로 기록한다.
- 이유: Supabase, Netlify, 장비 상태를 파일만으로 확인할 수 없다.

## D-005 — 안전 인터록은 서버 강제가 확인되기 전까지 "미완"으로 둔다

- 날짜: 2026-09-19
- 결정: 안전점검 PASS·기상 잠금·마감 잠금은 클라이언트 구현만으로 완료 판정하지 않는다. 서버(RLS/트리거/RPC) 강제가 확인될 때까지 "부분 구현"으로 기록한다.
- 이유: `database/FINAL_SUPABASE_SETUP.sql:824-841`이 운영 테이블에 anon `using(true)` 정책을 만들므로, 브라우저 밖에서 anon 키로 직접 호출하면 인터록을 우회할 수 있다.

## D-006 — 스냅샷 제외 목록에 `fugu`를 포함한다

- 날짜: 2026-09-19
- 결정: `fugu/config.json`의 `snapshot.excludeDirectories`에 `fugu`를 추가한다.
- 이유: D-003(기억 문서를 배포 산출물에서 분리)의 이행. `fugu`는 프로젝트 루트 안에 있어 그대로 두면 스냅샷·배포 검사 목록에 감사 문서와 내부 경로가 섞인다.

## D-007 — 회계 최소셋은 간편장부 양식이 아니라 복식부기 원장을 본체로 둔다

- 날짜: 2026-09-19
- 결정: 간편장부는 세법이 요구하는 출력 양식으로 취급하고, 시스템의 데이터 구조는 계정과목 → 전표(차변/대변) → 시산표로 만든다. 손익·부가세 신고자료·간편장부는 원장에서 파생된 출력으로 본다.
- 이유: 간편장부 양식을 그대로 스키마로 쓰면 거래처별 채권·채무, 부가세 대사, 자금 흐름, 대차평형 검증이 불가능해진다. 엑셀 → 시트 → DB로 이전할 때 구조를 버리지 않기 위해서도 원장 구조가 필요하다.
