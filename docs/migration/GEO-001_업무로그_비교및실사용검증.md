## 실사용 연결 경로: 직접 관찰과 미검증 구분

1. **GitHub:** 현행 기준은 위 `bb0fcec…`이며 업무로그 폴더의 마지막 파일 변경은 2026-09-29의 `3bada78`로 표시됐다. [현행 파일][current-tree].
2. **Netlify:** 로그인된 별도 팀의 [`bongplaychat2` 프로젝트][netlify-project]를 발견했다. [게시 중인 배포 상세][netlify-deploy]는 **Sep 17 at 1:13 PM**(Netlify 화면 표기), 상태 `published`, **Netlify Drop** 수동 배포, `api` 함수 1개 배포/활성, 리디렉션 1개와 헤더 규칙 1개 처리. Git 소스 브랜치·커밋 SHA는 이 방식으로 제공되지 않는다. 프로젝트는 공개 사이트지만 관리 프로젝트는 Private 표시. 팀의 운영 크레딧 제한으로 신규 production deploy는 현재 일시중지 안내가 표시됐다. 환경변수 이름 `GEMINI_API_KEY`, `SAKANA_API_KEY`, `SHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY`만 보였고 값은 열지 않았다. `ACCESS_CODE`, `LLM_PROVIDER`, `SHEET_NAME` 항목은 목록에 보이지 않았다.
3. **배포 버전 구분:** 실제 [`https://bongplaychat2.netlify.app/`][live-site]의 HTML 원문은 현행 `public/index.html`과도 구 `netlify-site/public/index.html`과도 **바이트 동일하지 않다**(관찰된 문자 길이 각각 30,165 / 31,902 / 27,839). 현행 UI의 시트 서식 버튼은 배포 화면에 없고 배포 화면의 아카이브 링크는 `/archive`이다. 따라서 아래 실배포 문제를 `master`의 실동작 결함으로 단정하지 않는다. 배포 함수 바이너리와 Git blob 일치 여부는 미검증이다.
4. **업무로그 화면:** 자동 저장 체크는 ON. 접근 코드 입력란은 표시되지 않았다. 원장 로딩 후 **48행**, 분류별 결정 6·할일 24·공유 6·아이디어 12를 표시했다. 빈 입력으로 `AI로 자동 분류` 클릭 시 `먼저 대화 내용을 붙여넣어 주세요.`가 표시됐고 기록은 생성되지 않았다. `연결 상태 → 확인`은 파일 제목 `bongchat`, 시트 ID 끝 **`u1NEDBvQ`**, 탭 `업무로그`, 데이터 **48행**, 헤더 `타임스탬프 | 분류 | 핵심 요약 | 담당자`, 제공자 `sakana`를 반환했다. 서비스 계정 주소와 마지막 기록 내용은 보고서에 적지 않는다.
5. **Google Sheets:** 화면의 `시트 열기` 링크가 가리키는 ID와 Drive에서 열어 본 `bongchat` 파일 ID가 일치했다(끝 `u1NEDBvQ`). 로그인된 Google 계정에서 **보기 전용**이며, 화면의 탭은 `업무로그`. 첫 행 A–H가 `타임스탬프/분류/핵심 요약/담당자/마감일/우선순위/상태/원문 맥락`이었다. 읽기 도구로 관찰한 헤더 포함 49개 행과 진단의 데이터 48행은 일치하나, 읽기 도구의 범위는 전체 시트 보증이 아니므로 저장 성공 증빙으로 해석하지 않는다. 시트의 실제 행 내용·계정 식별자는 공개 저장소에 옮기지 않았다.
6. **아카이브(별도 자산):** 실배포 [`/archive`][live-archive]는 로딩 초기에 코드 내 샘플 4개를 잠깐 보여준 뒤 Google Apps Script 목록 결과로 **73개**를 표시했다. 다섯 고정 분류 카운트는 모두 0이며 `시설안전 및 보수`를 누르면 `0개 항목/보관된 미디어가 없습니다`가 나온다. 다시 `전체`로 복원했다. 실제 항목 분류명이 고정 5종과 다르다. `/archive`는 업무로그 시트가 아니라 Drive GAS/로컬 캐시/샘플 데이터를 쓰며, 배포 코드에서는 URL이 있다는 이유만으로 `연동중` 배지를 먼저 표시한다. 이미지/파일명·기록 내용은 증거로 저장하지 않았다.

## 결론과 다음 작업 (최대 3개)

- **유지:** 현행 Netlify 분류·정규화·저장 수/범위 확인·원장·연결 진단. 구 `README.md`/`netlify.toml`은 동일 blob이므로 별도 이관 불필요.
- **선택 이관:** 구 Apps Script의 직접 시트 접근·잠금·검토 UI는 현행과 중복될 수 있다. 실제 사용자와 원장 단일화 방침을 정한 뒤 필요한 기능만 분리 검토. seed는 구버전 참고로 보존하고 운영에 재적재하지 않는다.
- **수정 필요:** (1) 접근 코드/인증 정책 및 공개 원장 범위, (2) 저장 후 초안 제거와 append 멱등성, (3) 아카이브 분류 매핑·샘플/실데이터 상태 표시.
- **추가 확인:** 분리된 테스트 배포+테스트 시트, 배포 산출물과 Git SHA의 추적, 모바일 표시와 시트 전후 행수 검증. 관찰 당시 운영 데이터나 배포를 변경하지 않았다.

**후속 제안 3개:**
1. Ben이 운영 접근 정책·공개 범위와 테스트 배포/시트 소유자를 확정하고, Netlify 배포 추적/크레딧 제한을 담당자에게 조정한다.
2. 별도 구현 PR에서 저장 완료 시 초안 정리와 append 멱등키/중복 방지를 추가하고 합성 표식으로 시트 전후 행수·빠른 더블클릭·재전송을 검증한다.
3. 별도 아카이브 PR에서 Drive 반환 카테고리와 UI 분류를 맞추고, 샘플/캐시/실시간 상태를 구분해 73개 데이터의 필터 회귀 시험을 한다.
