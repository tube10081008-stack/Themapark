# ANT-005 골격 검토 R1

벤 / 2026-10-06 / 대상 `5473285da9a03b194e096a7e1d718993a96c8fcb`.
아난티의 진행 중 골격을 검토했다. 최종 완료 보고로 해석하지 않는다. 아래 수정은 아난티 소유이며 벤은 구현 파일을 변경하지 않았다.

## R1 — history 필드 계약 불일치 (통합 전 필수)
consultation.js의 trimHistory/push와 rate-limit.mjs의 sanitizeHistory가 `{role,text}`를 사용한다. 인수 계약과 독립 QA 도구는 `{role,content}`를 사용한다.
해당 원격 모듈을 별도 파일로 읽어 실행한 결과 `sanitizeHistory([{role:'user',content:'보호자는요?'}])`가 빈 배열을 반환했다.
수정: UI/서버/공급자/시험을 content로 일치시키고 알 수 없는 역할은 계약대로 거부한다. 임의로 QA 도구를 text에 맞추지 않는다. 필요하면 명시적 버전 전환안을 먼저 제시한다.

## R2 — 서버 문맥 축소가 최신 발화를 제거 (재현 완료)
800자 A/B/C/D/E/F 발화 6개를 sanitizeHistory에 넣으면 A/B/C/D를 남긴다. 최신 E/F가 빠져 사용자의 최근 정정이 사라진다.
수정: 정제 후 오래된 발화를 앞에서 제거해 총 3,200자 이내의 최신 문맥을 유지한다. 같은 입력의 기대값은 C/D/E/F다. UI와 서버 각각 시험한다. 개인정보 포함 발화 제거와 개수 제한도 같이 유지한다.

## R3 — 새 대화 세대 확인 시점 (코드 검토, 화면 재현 대기)
fetch가 Response를 반환한 직후에는 세대를 확인하지만 `await res.json()` 뒤에는 확인하지 않고 답변을 출력·history에 추가한다. 응답 본문을 읽는 동안 새 대화를 누르면 이전 응답이 새 창에 들어갈 수 있다. 성공/429/입력 오류 모두 비동기 body 읽기 이후 DOM 변경 전에 세대를 확인해야 한다.
타임아웃도 fetch 헤더 수신 시 해제되어 body 읽기에는 적용되지 않고, fetch 예외에서는 timer가 정리되지 않는다. timer는 try 바깥에서 만들고 finally에서 정리해 body 읽기까지 제한한다.
필수 재현: 헤더 반환 후 body를 지연시키고 새 대화 → 새 질문 → 과거 body 해제. 과거 문장·history 혼입이 0이며 새 요청 busy 상태가 유지되는지 확인.

## R4 — 한글 본문 상한 (계약 인계)
현재 핸들러 8,192바이트 한도는 질문 1,200자와 history 3,200자의 한글을 모두 담지 못한다. 각 필드 길이 제한과 별도로 UTF-8 body 상한을 정하고 정확 경계/초과 경계를 시험한다. 본문을 무제한 읽는 방식으로 해결하지 않는다.

## 아직 구현을 기다리는 부분
consultation.mjs/decision-engine/model-provider는 이 커밋에서 history를 전달·사용하지 않는다. 따라서 골격 시험 성공을 실제 다중 턴 이해 성공으로 보고하면 안 된다. 이는 보고된 단계의 후속 구현 범위로 구분한다.

실제 브라우저·실모델·40개 CS 평가: 아직 미실행. 코드 경로 분석과 위 두 sanitizeHistory 재현 결과만 확인했다.
