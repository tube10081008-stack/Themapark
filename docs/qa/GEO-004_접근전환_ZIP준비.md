# GEO-004 — 직원 전용 접근 전환 영향과 ZIP 배포 검증 준비

**운영 자산은 읽기만 했다.** 운영 공유·권한·소유권·Apps Script 배포·환경변수·Netlify 설정을 바꾸지 않았고, 웹 앱 API를 직접 호출하지 않았다. Apps Script 편집기는 열람만 했고 저장하지 않았다. 계정 주소·직원 명단·공유 URL·Drive/Apps Script/시트 식별자·서비스 계정·비밀값은 적지 않는다. 식별자는 값끼리 같은지만 비교했다. 관찰 시각 2026-10-01 10시대(KST). 벤 결정(2026-10-01 12:19 KST) 이후 승인 범위의 분리 시험 자산만 새로 만들었다(5절).

## 벤 우선 확인 사항

1. **업무로그 원본 시트가 "링크가 있는 인터넷상의 모든 사용자 뷰어"로 공유돼 있다.** 공개 업무로그 화면에는 이 시트로 가는 `시트 열기` 링크가 있다. 즉 화면·API 보호와 별개로 원장 원본이 링크만으로 열린다. 아카이브 Drive 루트 폴더도 같은 링크 공유 상태다.
2. **아카이브 Apps Script 웹 앱은 "소유자 계정으로 실행, 액세스 권한: 모든 사용자"로 배포돼 있다.** 코드에는 호출자 확인이 없고, 업로드·새 폴더 때마다 개별 파일·폴더에 링크 공유를 다시 건다. 따라서 루트 폴더 공유만 바꾸면 개별 파일의 링크 공유가 남는다.

### 원본 접근 제한 시험 절차 (테스트 환경 전용, 운영에서 실행 금지)

준비: 운영과 분리된 시험 Drive 폴더·시트·빈 Apps Script 프로젝트는 벤 결정 범위에서 준비했다(5절). 시험용 Apps Script 코드와 별도 배포, 합성 이미지 3장, 직원/비직원 역할 계정, 쿠키 없는 브라우저 프로필은 아직 없으므로 아래 절차는 미실행이다.

1. 기준선: 공유 상태와 파일별 공유 목록을 기록한다. 비로그인 프로필에서 썸네일·원본 링크 응답을 기록한다.
2. 테스트 Apps Script에서 링크 공유 설정 코드를 제거한 새 버전을 배포한다.
3. 루트와 하위 폴더, 기존 파일 각각의 링크 공유를 해제하고 테스트 직원 계정만 추가한다.
4. 검증: 비로그인과 비직원 계정은 목록·썸네일·원본·업로드·폴더 생성이 모두 거부된다. 직원 계정은 목록·썸네일·원본·업로드가 허용되고 삭제는 거부된다. 관리자만 삭제(휴지통)가 허용된다(ANT-003 설계 기준).
5. 새로 업로드한 파일이 링크 공유 없이 생성되는지 확인한다.
6. 업무로그 테스트 시트에서 링크 공유를 해제한 뒤 서비스 계정 경유 조회·쓰기가 정상인지, 비로그인 시트 링크가 거부되는지 확인한다.
7. 복구(시험 자산 한정): 시험 Apps Script를 이전 버전으로 되돌려 동작이 회복되는지 확인한다. 공유는 차단 상태를 유지하며, 공개 링크로 되돌리는 절차는 시험하지 않는다.

## 3. 수동 ZIP 배포 체크리스트

### 프로젝트별 필수 구성 (저장소 `ded2f1c` 기준 소스 분석)

| 항목 | bongplay (01) | bongplaychat (04) |

| 저장소 밖 필수 설정 | `assets/config.js`(git 제외, **브라우저 공개 파일**: 비밀값 금지), 있으면 `pages/firebase-config.js` | 없음(비밀값은 Netlify 환경변수) |

| 공통 | 커밋 SHA 기록·버전 표식이 없다. `.gitattributes`가 없어 줄끝(CRLF/LF)에 따라 파일 해시가 달라질 수 있다 | 같음 |

### 배포 전

- [ ] 검토·병합된 master SHA를 정하고 깨끗한 checkout에서 작업한다(`git status --porcelain` 비어 있음). 해당 폴더 SHA와 PR 번호를 기록한다.
- [ ] 저장소 밖 설정(`config.js` 등)은 공개 값만 들어 있는지 확인한다. 비밀값·암호·서버 키가 없어야 한다.
- [ ] ZIP을 만든 뒤 파일 목록을 확인한다. `.env`, `*.key`, `*.pem`, `.sql`, `.py`, `.md`, `.gs`, 원시 데이터, 다른 폴더 파일이 없어야 한다.
- [ ] ZIP SHA-256, 파일 수, 크기를 기록한다.
- [ ] 버전 표식을 확인한다(예: `sw.js` 캐시 이름). 표식 파일 추가 여부는 결정 요청 4번.
- [ ] 로컬 정적 서버 스모크: 첫 화면, 직원 화면 인증 창, `pages/archive`, 공개 금지 경로 404. 함수는 로컬에서 실행되지 않으면 미실행으로 기록한다.
- [ ] 직전 published 배포 ID를 복구 기준으로 기록한다(현재 위 표).
- [ ] Apps Script·Drive·시트 변경이 함께 있으면 순서를 정한다(서버·권한 → 화면). 각 변경 전 상태와 버전 번호를 기록한다.

### 배포 후

- [ ] Netlify에서 새 published 배포 ID·시각(KST)·파일 수·함수 수를 기록한다.
- [ ] 도메인에서 주요 파일을 받아 ZIP 안 파일과 비교한다. Netlify가 자동으로 넣는 호스팅 주석·HUD 스크립트·링크 경로 변환은 제외하고 비교한다(GEO-002 방법).
- [ ] 화면 확인: 인증 창, 아카이브 11분류와 폴더별 수, 업무로그 연결 진단(행 수만), 쿠키 없는 세션에서 목록·원장 거부.
- [ ] 배포 기록표에 도메인 / 배포 ID / 시각 / master SHA / ZIP SHA-256 / 담당 / 스모크 결과 / 직전 배포 ID를 남긴다. GitHub 병합과 운영 배포 완료는 따로 보고한다.

### 복구

- Netlify: Deploys에서 직전 배포를 다시 게시(Publish deploy)한다. Drop 배포도 이력이 남아 있다.
- Apps Script: 배포 관리에서 이전 버전(현재 활성 = 버전 2)으로 되돌린다.
- Drive·시트 공유: 장애 시 **접근 차단/점검 상태를 유지**하며 복구한다. 공개 링크 복원은 승인되지 않았고, 공개 범위 확대는 별도 대표 결정이 필요하다. 변경 전 공유 기록은 영향 분석용이며 공개 상태로 자동 복원하지 않는다.
