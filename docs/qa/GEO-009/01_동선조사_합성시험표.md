## 0. BEN-026 인수 후 확정 기술 결정 (2026-10-11)

- **서로 다른 모수:** 방문 계획 선택, 전화 문의, 실제 현장 방문을 각각 별도 분모·사건으로 집계한다. 계획·문의가 실제 방문으로 자동 승격되지 않으며, 전환은 연결된 사건과 기준 시각이 확인될 때만 계산한다.

## 4. 합성 독립 검증 공통 규칙

- **모든 케이스 미실행.** 아래는 실행 방법·기대 결과다. 성공 UI만으로 통과 처리하지 않는다.
- 시험 전 벤 계약에서 사건 ID, 발생·서버 수신 시각, 상태 정의, 별도 모수(방문 계획·전화 문의·실제 방문)와 분자, 집계 지연 상한, 마지막 갱신 기준, 오류 코드를 받아 판본에 고정한다. 분모 0은 `계산 불가`, 비용 null은 `미입력`, 명시적 0은 확정 0으로 적용한다. 실험별 사전 표본 계획이 없으면 `판단 보류`로 고정한다.
- 합성 고객 A/B, 직원 S1/S2, 상담 채널 C, 방문 건 V를 분리해 사용. 운영 계정·전화·카드·실제 고객 식별자를 쓰지 않는다.
- 증거: 화면 캡처(민감값 가림), 요청/응답의 **필드명·상태·코드만** 남긴 마스킹 기록, 읽기 전용 시험 스토어의 사건 ID·상태·서버 시각·집계 반영 시각, 두 화면 캡처의 KST 시각. 원본 토큰·URL·개인정보는 저장소에 넣지 않는다. R1에 실제 원장이 없으므로 저장·적재 검증은 **미실행/후속 서버 검증**으로 둔다.
- UI 표시 판정과 **서버 기록**, **분석 적재/집계** 판정을 분리한다. 각 단계의 증거가 없으면 해당 단계는 미검증이다. 조회 실패를 빈 데이터로 바꾸거나, 누락 비용을 0원으로 대치하지 않는다.
