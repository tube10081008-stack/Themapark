## 4. 합성 독립 검증 공통 규칙

- **모든 케이스 미실행.** 아래는 실행 방법·기대 결과다. 성공 UI만으로 통과 처리하지 않는다.
- 시험 전 벤 계약에서 사건 ID, 발생·서버 수신 시각, 상태 정의, 모수·분자, 집계 지연 상한, 마지막 갱신 기준, 오류 코드, 비용의 `미입력/미정/0원` 구분을 받아 판본에 고정한다.
- 합성 고객 A/B, 직원 S1/S2, 상담 채널 C, 방문 건 V를 분리해 사용. 운영 계정·전화·카드·실제 고객 식별자를 쓰지 않는다.
- 증거: 화면 캡처(민감값 가림), 요청/응답의 **필드명·상태·코드만** 남긴 마스킹 기록, 읽기 전용 시험 스토어의 사건 ID·상태·서버 시각·집계 반영 시각, 두 화면 캡처의 KST 시각. 원본 토큰·URL·개인정보는 저장소에 넣지 않는다. 시험 DB가 없으면 저장·적재 검증은 **미실행**으로 둔다.
- UI 표시 판정과 **서버 기록**, **분석 적재/집계** 판정을 분리한다. 각 단계의 증거가 없으면 해당 단계는 미검증이다. 조회 실패를 빈 데이터로 바꾸거나, 누락 비용을 0원으로 대치하지 않는다.
