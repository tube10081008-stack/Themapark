## P1: 모델 생성 후속 문장으로 잘못된 요금·예약 완료가 고객에게 노출됨
validateModelResponse는 opening에 숫자/일부 약속 검사를 하지만 follow_up에는 개인정보 표현·물음표 개수만 검사한다. 다음 모의 응답은 검증에 통과하고 HTTP 핸들러 결과에도 그대로 나타났다.

```json
{"action":"answer","knowledge_ids":["price.guardian"],"opening":"","follow_up":"보호자 입장권은 100원이며 예약도 완료됐어요.","handoff_reason":null}
```

실제 재현: HTTP 200, mode=model, 승인된 5,000원 안내 뒤에 100원/예약 완료 문장이 붙는다. 이는 모델이 항상 이렇게 말한다는 뜻이 아니라 서버가 이를 차단하지 못한다는 증거다.
수정: 모든 생성 문자열에 같은 사실·약속 제약 적용. 숫자뿐 아니라 '예약됐어요', '음료는 무제한이에요', '언제든 오세요' 등 비수치 주장 시험. 검증 실패 문장은 폐기. 자유 문장 검증의 한계를 인정하고 공감·질문 선택 계약/검토된 변형을 이용해 사실 서술과 분리할 것.

## P1: 인사/특정 시험 문구가 실제 질문·문맥보다 먼저 처리됨
- '안녕하세요 보호자 가격을 알려주세요' → 인사만 하고 '어떤 점이 궁금하세요?'로 되묻는다.
- 이전 질문 '기본권만 이용하려고 해요' + '아이 2명이면 표값만 얼마죠?' → 문맥을 보지 않고 종합권 21,000원으로 답한다.
- 환불이라는 단어만 있으면 고객이 말하지 않은 '안내가 달라 혼란스러우셨겠어요'를 붙인다.
수정: 단독 인사·감사만 로컬 처리. 실제 문의/지시어가 있으면 문맥 기반 모델 경로를 사용. CS 시험 문구 전용 분기는 제거하고 미공개 변형 문장으로 검증한다. 표값 계산은 별도 산술 계약 전에는 임의 확정하지 않는다.

## P1: R1 history 계약·최신 문맥·새 대화 경쟁 문제 미반영
- UI/정제기는 여전히 text 사용. 계약대로 content를 보내면 제거된다. 캡처한 모델 요청에서도 history가 사라졌다.
- 800자 A~F 6개 → 서버가 A/B/C/D 보존. 기대 C/D/E/F.
- consultation.js는 R1 이후 변경되지 않아 body 읽기 뒤 세대 재확인·finally 타이머 정리도 아직 없다. 이 항목은 코드 검토이며 브라우저 경쟁 상황 재현은 남았다.
- body 한도를 32,768바이트로 올린 수정은 확인했다. 정상 최대 한글 대화/바이트 초과 경계 테스트 결과도 제출할 것.

## P1: 준비한 CS 정책·지식 설명이 모델에 전달되지 않음
실제 모의 전송 캡처에서 system에는 짧은 일반 지시만 있고, 사용자 메시지에는 candidate_ids만 있다. getAvailableKnowledgeBlocks의 text는 전달하지 않는다. persona.md/cs-policy.md의 핵심 규칙과 지식의 의미·제약이 실제 모델 요청에 들어가야 한다. 파일이 저장소에 존재하는 것만으로 교육 적용 완료가 아니다.
history는 과거 assistant 문장을 독립 사실 근거로 받아들이지 않도록 비신뢰 데이터 경계를 명시한다. 공급자 호출 코드가 새 엔진 안에 직접 들어갔으므로 공통 어댑터와 분리해 공급자 교체 계약도 유지한다.
