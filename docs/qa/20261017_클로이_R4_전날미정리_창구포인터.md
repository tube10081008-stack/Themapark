## 3. 구현 (d78a8cb, `PROPOSED_MIGRATION_ticket_queue.sql`)

함수 서명·권한·표·열·제약은 바꾸지 않았다. 매표 화면은 수정할 필요가 없다. 기존 설치 DB 에는 이 파일만 다시 실행하면 된다 (CREATE OR REPLACE).

| 벤 기준 | 구현 |
|---|---|
| 과거 원장·order_id 보존 | 대기열 RPC 는 원장 표를 쓰지 않는다. 전날 processing 팀은 직원이 **같은 order_id** 로 `complete_queue_issuance` 를 부를 때만 완료된다 (원장 대사는 그대로). 원장이 있는 전날 팀의 취소는 `ORDER_RECORDED` 로 거부한다 |
| 자동 취소·발권 완료 금지 | 자동 정리 작업 없음. 조회·호출은 전날 행을 바꾸지 않는다 (P1·S1 시험에서 행 불변 확인) |
| 오늘 점유와 과거 미정리 구분 | 점유는 오늘 행(`queue_date = KST 오늘`, called/processing, desk_no)으로만 판정한다. 직원 목록이 `desks[].pointer_state`(empty/ok/stale/missing)·`occupant`·`pointer_stale.reason`(past_day/inactive/other_desk/not_found)과 `past_unresolved_teams`(기록된 주문·`allowed_actions`)를 따로 돌려준다 |
| 변경 RPC 의 잠금·재조회 | 직원 변경 RPC 8개는 인증 뒤 **시설 단위 advisory lock**(`private.lock_ticket_queue_site`) → 대상 행 `for update` 재조회(`site_id` 확인) → 판정 → 쓰기 순서다. 시설 단위라 자정을 사이에 둔 두 요청도 직렬화된다. 포인터는 잠금 안에서 `private.ticket_queue_sync_pointer` 로만 바꾼다 |
| 조회 RPC 숨은 쓰기 금지 | `get_staff_queue_list` 는 대기열·창구·원장 표를 쓰지 않는다. stale·missing 은 보고만 하고 고치지 않는다. 유일한 쓰기는 FINAL 의 기존 인증 기록 `private.auth_attempts` 다 (IP 잠금용, 변경 없음) |

그 밖의 변경:
- 재호출·처리 시작의 창구 이동은 대상 창구 점유를 확인한다 (`DESK_ALREADY_OCCUPIED` + `occupant`).
- 전날 행의 재호출·처리 시작·보류·복귀는 `PAST_QUEUE_DATE` 로 거부한다.
- 호출은 잠금 안에서 창구 행을 `for update` 로 다시 읽는다 (정지가 이김). 성공 응답에 `replaced_pointer` 를 더한다.
- 완료·취소 응답에 `queue_date`·`past_queue_date` 를 더한다.
- 내부 함수 7개는 모두 PUBLIC·anon·authenticated 실행 권한을 회수했다.
- 설치 묶음:
  - `60_verify` 에 Q04(함수 존재)·Q05(API 역할 비노출)를 더했다. 일부러 권한을 준 상태에서 Q05 가 잡는 것도 확인했다.
  - `90_reset_queue` 가 새 함수까지 지운다.

- **시험 브라우저 시간대를 `Asia/Seoul` 로 고정.**
  - 화면은 오늘 날짜를 단말 시간대로 계산한다 (`BongplaySync.toLocalDateStr`).
  - 컨테이너 기본 UTC 로는 KST 00:00~09:00 에 화면의 '오늘'이 전날이 된다. 그러면 서버 PASS 점검을 못 찾아 호출이 막혔다 (이번 실행 시간대에 처음 드러남).
  - 현장 단말(KST)과 같은 조건으로 맞춘 것이다. 프런트에 대한 관찰은 §7 에 적었다.

## 7. 결정 요청·전달 사항

1. **(벤) 오늘 처리 중 팀의 취소 가드**: 원장이 저장된 오늘 팀의 대기열 취소도 `ORDER_RECORDED` 로 막을지 정해 주세요.
   - 계약 §7 대로 이번에는 과거 행에만 적용했다. 오늘 행까지 막으면 화면의 [접수 취소] 동작이 바뀐다.
2. **(벤→아난티, 요청 시)** 직원 화면에 전날 미정리 팀을 표시하는 UI가 필요하다.
   - 서버는 `past_unresolved_teams`·`allowed_actions`·`recorded_orders` 를 이미 돌려준다.
   - 화면은 이 정보로 [같은 주문으로 완료]·[취소] 를 제공할 수 있다. 프런트 범위라 손대지 않았다.
3. **(아난티 참고)** 화면의 '오늘'은 단말 시간대 기준이다.
   - 단말 시간대가 KST 가 아니면 00:00~09:00 KST 에 안전점검 판정·날짜 조회가 전날로 계산된다.
   - 서버는 KST 기준이다. 현장 단말이 KST 이면 문제없다.
4. called 상태인데 기록된 주문이 있는 전날 팀은 `allowed_actions: []`·`LEDGER_REVIEW_REQUIRED` 다.
   - 화면 흐름(처리 시작 → 원장 저장)에서는 생기지 않는 상태다.
   - 생기면 기존 환불(원장 취소)로 정리한 뒤 취소해야 한다.
