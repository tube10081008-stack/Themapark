## 벤 우선 확인 사항

내부 아카이브 `bongplay.netlify.app/pages/archive`에서 **미인증 상태(직원 세션 없음, 인증 창 표시)인데도 페이지가 Apps Script에서 폴더 목록과 전체 파일 목록을 받아(200) 73개 카드를 인증 창 아래 화면 구조에 그렸고 썸네일 20개를 불러왔다.** 인증 창은 화면을 덮을 뿐이고 아카이브 데이터 경로는 막지 않는다. 기존 봉챗 아카이브 `bongplaychat.netlify.app/archive.html`은 인증 창도 없다. 두 입구는 같은 Apps Script와 같은 Drive 루트 폴더를 쓰므로, 어느 입구를 표준으로 하든 **자료 공급원 쪽 보호가 없으면 직원 전용이 되지 않는다.**

## 자료 공급원과 폴더 식별

- **같은 공급원(소):** 라이브 두 아카이브와 저장소 master에 들어 있는 Apps Script 웹 앱 주소는 모두 같은 값이다. 코드 안의 Drive 루트 폴더 주소도 두 라이브 판이 같다. 내부 아카이브는 공통 설정 파일(`assets/config.js`)의 아카이브 주소를 먼저 읽는다. 이 설정 파일은 저장소에 템플릿만 있고 라이브에서는 공개 파일로 제공된다.
- **폴더 식별(소):** 분류는 폴더 **이름**(`NN_이름`)으로 식별하고 필터와 업로드 대상도 이름 문자열을 쓴다. 폴더 ID로 식별하지 않는다.
- **같은 자료(관):** 두 화면의 폴더별 수가 11개 폴더 모두 같고 합계 73이다.
- **Apps Script 코드(소, 저장소 기준):** `01_…/assets/drive-archive.gs`와 `docs/apps_script_archive.gs`는 같은 파일이다. `doGet`(ping·folders·categories·list)과 `doPost`(upload·createFolder·delete·deleteFile) 어디에도 호출자 인증·토큰 검사가 없다. 업로드 파일을 "링크가 있는 모든 사용자" 공유로 설정하는 코드가 있고, ping은 루트 폴더 이름과 ID를 돌려준다. **라이브에 배포된 Apps Script가 이 저장소 코드와 같은지는 확인하지 못했다(미).**

## 직원 전용 정책을 위해 보호할 대상

인증 창이 있다는 것과 데이터 접근이 통제된다는 것은 다르다.

| 대상 | 현재 상태 | 근거 |
|---|---|---|
| 내부 아카이브 화면 `/pages/archive`(+`.html`) | 인증 창 있음. 그러나 페이지 코드는 인증 여부를 확인하지 않고 목록을 불러옴 | 관(미인증 상태 요청 200·카드 73), 소(아카이브 코드에 인증 상태 참조 없음) |
| 봉챗 아카이브 `bongplaychat…/archive.html` | 인증 창 없음. 업로드 화면 노출 | 관 |
| Apps Script 목록·폴더·ping(GET) | 호출자 확인 없음(저장소 코드 기준) | 소 / 라이브 코드 미 |
| Apps Script 업로드·폴더 생성·삭제(POST) | 호출자 확인 없음(저장소 코드 기준). 라이브 화면에는 삭제 없음 | 소 / 미 |
| Drive 파일·썸네일 주소 | 업로드 시 링크 공유 설정 코드. 미인증 상태에서 썸네일 20개가 불러와짐 | 소 / 관 |
| 공개 설정 파일 | Apps Script 주소 등이 공개 파일에 있음. 주소를 숨기는 것만으로 보호가 되지 않음 | 관(200 제공) / 소 |
| 직원 세션 | 운영자 암호는 서버 함수(`verify_staff_access`)로 검증. 성공 후 입력한 암호 자체를 브라우저 저장소에 12시간 보관 | 소 |
| 기기 캐시 | 아카이브 목록 캐시가 브라우저 저장소에 남음(로그아웃과 무관) | 소 |

차단됨: 승인된 직원 세션이 없어 인증 뒤 화면의 조작·표시는 확인하지 못했다. 암호를 입력하거나 우회하지 않았다.

## 통합 시 유지·부족 기능과 전환 조건

**유지할 기능:** Drive 폴더 기반 11개 분류와 폴더별 수, 전체/분류 필터, 검색, 작성자·메모·촬영일시 표시, 사진·영상 확대 보기와 다운로드, 여러 파일 업로드, 새 폴더와 목록 숨기기, 캐시 후 실시간 갱신, 모바일에서 쓰기 쉬운 가로 폴더 줄.

**내부 아카이브(라이브)에 부족하거나 다른 점:** 코드 기본 분류 2개가 실제 폴더와 번호가 겹쳐 13개로 보임, 폴더 목록 캐시 없음, 폴더 탐색기가 세로 배치. 삭제·작성자 기억은 저장소에만 있고 두 라이브 모두 미배포이며 삭제는 권한 정책이 필요하다.

**전환 조건(제안):**
1. Apps Script 목록·업로드·폴더·삭제 경로에 서버 측 직원 확인을 넣고, 미인증 요청이 목록·썸네일을 받지 못하는 것을 테스트로 확인한다. 화면 인증 창만으로 완료 처리하지 않는다.
2. 아카이브 화면은 직원 세션 확인 뒤에만 목록을 불러오도록 하고 로그아웃 시 목록 캐시를 지운다.
3. 내부 아카이브에서 현행과 같은 11개 폴더·폴더별 수가 표시되는지 대조한다(기본 분류 중복 정리).
4. 두 입구가 같은 Apps Script를 쓰므로 공급원 보호를 바꾸면 두 입구가 동시에 영향을 받는다. 구 입구 폐쇄 전에 두 화면 모두의 호환 여부를 정한다.
5. 검토된 SHA를 적은 ZIP 배포 기록을 남기고 BEN-008 원칙에 따라 GitHub 병합과 운영 배포를 분리 보고한다.

**되돌리기 조건:** 자료는 Drive 한곳에 있으므로 입구 전환은 자료 이동 없이 메뉴 링크 되돌리기로 복구할 수 있다. 직전 배포(bongplay `6ab4ded0…`, bongplaychat `6ab74e7a…`)를 복구 기준으로 기록한다. Apps Script 인증 변경은 되돌릴 때 이전 웹 앱 버전으로 돌아가야 하므로 버전 번호를 기록한다. 자료 복사·재적재·구 입구 폐쇄는 이번에 하지 않았다.
