## 5. 결함 등록부 (Defect Register) 및 수정 상세

### [P0-1] 공용 키오스크/태블릿에서 타 고객의 개인정보(서약서) 노출 결함 (정정 보고)
- **심각도**: P0 (데이터 유출 및 개인정보보호법 위반 위험)
- **대상 파일**: `01_봉플레이_운영시스템/pages/consent.html` (577~595행)
- **정정된 재현 경로 및 분석**:
  - 원본 코드의 조건문은 4자리가 아니라 11자리 전체 일치(`digits.length === 11`)를 요구함.
  - 그러나 공용 단말기에서 이전 손님이 작성한 전체 서약 내역 배열(`bongplay_safety_consents`)이 로컬 스토리지에 그대로 평문으로 남아 있었으며, 재방문 확인 로직(`checkRepeatFamily`)이 해당 로컬 배열을 선형 탐색하여 번호 일치 시 가족 성명과 자녀 목록을 그대로 화면에 자동 완성함.
- **수정 내용**:
  - 로컬스토리지 전체 서약 목록(`bongplay_safety_consents`)에 대한 클라이언트 선형 탐색 폴백을 완전히 제거함.
  - 전용 캐시 키(`bongplay_family_${digits}`) 또는 백엔드 보안 RPC(`lookup_family_children`)만을 조회하도록 제한.
- **보안 경계 및 한계점 보고**:
  - 본 수정은 공용 단말기 브라우저에서 타인의 전체 서약 목록이 탈취되거나 화면에 누설되는 클라이언트 취약점을 제거한 것입니다.

### 7.1 [추가 조건 1] 안전서약 취소 서버 계약 및 실제 동기화 어댑터 5단계 전수 검증
- **제안 SQL 작성**: `01_봉플레이_운영시스템/database/PROPOSED_MIGRATION_safety_consents_cancellation.sql`
- **제안 내용**:
  ```sql
  alter table public.safety_consents
    add column if not exists status text default 'active',
    add column if not exists cancelled_at timestamptz,
    add column if not exists cancel_reason text;
  ```
- **운영 DB 안전 원칙 준수**: 운영 Supabase DB에는 직접 쿼리를 실행하지 않았으며, 오케스트레이터(벤) 검토 후 별도 배포 파이프라인에서 처리하도록 제안 파일로 격리함.
- **실제 동기화 어댑터 5단계 라이프사이클 검증 (`operations_integrity.test.js` 테스트 7)**:
  1. **호출자 원본 불변 및 영속 큐 적재**: `BongplaySync.patch` 호출자의 입력 객체를 `delete patchData['status']` 등으로 변조하지 않고 보존하며, 네트워크 오류/500 장애 시 로컬 `bongplay_outbox_queue_v2`에 원본 payload 전체를 영구 보존.
  2. **프로세스/브라우저 재시작 복원**: 재기동 후에도 `getPendingCount()`가 1건을 정확히 복원 유지.
  3. **재연결 및 아웃박스 방출 (Flush)**: 온라인 재연결 시 `flushOutbox()`가 Supabase로 PATCH 페이로드를 안전 전송하고 미전송 큐를 0으로 해소.
  4. **타 단말 동기화 전파**: 다른 단말(Device B)에서 `pullAll()` 실행 시 수신 데이터에서 취소 상태(`status: 'cancelled'`)가 유실 없이 로컬 캐시에 즉시 반영.
  5. **미적용 DDL(스키마 캐시 부재) 분기 가드 및 보류 보존 (벤 최신 리뷰 해결)**: 운영 DB에 제안 SQL이 아직 미반영되어 PostgREST 400 (`Could not find the 'status' column...`) 에러를 반환하는 경우, 호출자 객체에서 상태 컬럼을 임의 제거하여 가짜 성공(200)을 반환하지 않음. 전체 payload를 아웃박스(`bongplay_outbox_queue_v2`)에 안전하게 보존하고 `{ ok: false, schema_blocked: true, queued: true }`를 반환하여 보류 상태(`pending: 1` 유지)를 명시함. 이후 DB 마이그레이션이 반영된 후 `flushOutbox()`를 재실행하면 `status: 'cancelled'`가 온전하게 전송되어 큐가 해소(`pending: 0`)됨을 실제 어댑터로 완결 검증.
