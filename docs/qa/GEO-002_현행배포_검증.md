## 1. 배포 식별과 Git 대조

- 두 프로젝트 모두 대표가 열어 둔 Netlify 계정의 단일 팀에서 찾았다. 팀 목록에 다른 팀은 없었다. 이전 GEO-001의 chat2 팀과는 다른 계정이다.
- 배포 산출물에 Git SHA나 빌드 버전 표식은 없다. 공개 URL에서 받은 파일로 Git blob 해시를 계산해 `master`와 해당 경로의 과거 커밋 전부와 대조했다.
  - `bongplay`: `manifest.json`만 `master`와 바이트 동일. `index.html`은 Netlify가 자동으로 바꾼 부분(링크 경로 변환, 호스팅 주석·HUD 스크립트 삽입)을 빼면 `master`와 내용 차이가 없다. `sw.js`는 캐시 이름만 다르다: 배포 `bongplay-static-v2026-09-24r1`, `master` `...v2026-09-26r1`. **배포본은 master보다 이전 판이다.** 나머지 44개 파일(`pages/`, `assets/` 등)은 대조하지 않았다.
  - `bongplaychat`: `index.html`, `archive.html` 모두 어느 커밋과도 일치하지 않는다. 자동 변경을 뺀 뒤에도 `master`에만 있는 기능(시트 서식 버튼, 아카이브 삭제·작성자 저장 등)이 배포본에 없고, 배포본에만 있는 줄(분류 옵션을 목록에서 생성하는 코드 등)도 있다. **master와 다른 판으로 배포돼 있다.**
- 결론: "최신 ZIP 배포"는 대표 확인 사항으로 기록하되 **두 서비스 모두 현재 master와 동일하지 않다.** GitHub 병합이 Netlify 배포로 이어지지 않는 구조다(Drop 수동 배포).

## 2. 현행 화면 확인

세션 구분: (A) 대표가 로그인해 둔 브라우저. 이 사이트에는 쿠키가 없고 저장된 인증값도 없었다. (B) 쿠키 없는 HTTP 요청으로 원본 HTML만 받음(스크립트 미실행). **쿠키 없는 별도 브라우저 세션은 이 환경에서 브라우저 프로세스 실행이 차단돼 만들지 못했으므로, 렌더링된 화면 기준 무인증 확인은 미검증이다.**

### bongplay.netlify.app (운영시스템)

- 첫 화면: 게이트 없이 열리고 당일 요약(방문객·매출 미입력, 안전점검 미점검)과 메뉴가 보인다.
- 직원용 화면 `operations`, `safety-check`, `closing`, `management`, `consent-desk`, `gate`, `master`, `pages/archive`: 모두 "봉플레이 현장 운영 인증" 암호 입력 게이트가 떴다(세션 A). 암호는 입력하지 않았다.
- (B)에서 `pages/operations` 원본 HTML에는 게이트 전에도 목표 매출·BEP 같은 설정 수치와 빈 대시보드 틀이 들어 있다. 게이트가 화면 위에 덮는 방식이라 원문 전달 자체는 막지 않는다. 실제 운영 기록이 게이트 없이 불러와지는지는 확인하지 않았다.
- 메뉴의 봉챗 링크는 `https://bongplaychat.netlify.app`로 연결된다. 봉아카이브 링크는 같은 사이트의 `pages/archive`(게이트 있음)로 연결되어, 대표가 지정한 `bongplaychat.netlify.app/archive.html`과 입구가 다르다.

### bongplaychat.netlify.app (봉챗 업무로그)

- 운영시스템 메뉴에서 실제로 연결되므로 읽기 확인을 진행했다.
- 게이트: 접근 코드·암호 입력란이 없다(세션 A). (B)도 로그인 벽 없이 원본 HTML이 반환됐다.
- 원장: 전체 48행(결정 6·할일 24·공유 6·아이디어 12)이 표시됐다. 본문은 기록하지 않았다.
- 연결 진단(`확인` 버튼, 읽기): 파일 제목 `bongchat`, 시트 ID 끝 `u1NEDBvQ`, 탭 `업무로그`, 헤더 `타임스탬프 | 분류 | 핵심 요약 | 담당자`, 데이터 48행, 모델 표시 `sakana`. 화면의 시트 링크 ID 끝도 같다. 자동 저장 체크는 기본 ON이다.
- 따라서 GEO-001의 chat2 관찰(게이트 없음, 48행)은 **같은 시트를 쓰는 현행 업무로그에서도 세션 A로 재확인됐다.** 무인증 렌더링은 위와 같이 미검증이다.

### bongplaychat.netlify.app/archive.html (봉아카이브)

- 게이트 없음. 업로드 입력창과 저장 버튼도 보이지만 업로드는 시험하지 않았다.
- 분류: 11개 폴더(01~11). 전체 73개이며 폴더별 수는 06=1, 07=38, 09=18, 10=13, 11=3, 나머지 0으로 합계가 맞다. 07·09·10·06·11을 차례로 눌렀을 때 각 목록 수가 버튼 숫자와 일치했고 전체로 되돌렸다. **GEO-001 chat2의 "분류 0건" 문제는 현행 아카이브에서 재현되지 않았다.**
- 실데이터/샘플: 코드 내 샘플 4개는 보이지 않았다. 새로고침 후 Apps Script `folders`·`list` 요청이 모두 200으로 끝났고 표시 73개가 유지됐다. 브라우저 캐시에도 73개가 있어 첫 표시는 캐시일 수 있다.

## 3. 테스트 환경

- 운영 계정 팀의 Netlify 프로젝트는 `bongplay`, `bongplaychat` 2개뿐이다. 이전 chat2 팀에는 `replayce`, `bongplaychat2`, `bongplay2`가 있다. 테스트 전용 배포는 보이지 않았다.
- 접근 가능한 Google Drive에서 업무로그 시트는 `bongchat` 하나뿐이었고 테스트용 시트는 찾지 못했다. **분리된 테스트 배포·시트는 확인되지 않는다.** 새로 만들지 않았다.

## 후속 권고

1. 대표·벤이 업무로그와 archive.html의 공개 범위를 결정한다. 공개가 의도가 아니면 접근 보호가 필요하다. 운영시스템의 클라이언트 게이트도 원문·데이터 전달을 막지 않으므로 서버 측 보호 여부를 별도 검토한다.
2. 배포와 Git을 연결할 방법(Git 연동 배포 또는 ZIP에 커밋 SHA 표식 포함)을 정하고, 재배포 전 차이 파일 목록을 확인한다. 현재는 두 서비스 모두 master와 다르다.
3. 운영시스템의 봉아카이브 입구(`pages/archive`)와 실제 사용 중인 `bongplaychat.netlify.app/archive.html` 중 어느 쪽을 표준으로 할지 정한다.
4. 쓰기·중복 시험을 하려면 분리 테스트 배포와 테스트 시트를 먼저 마련한다. 이번 작업에서는 만들지 않았다.
