# BEN-016 — 모델과 독립된 지식·판단 백엔드 / Sakana Fugu 연결

2026-10-05 대표 정정 반영. JEV는 이 프로젝트에서 생성보다 선택을 우선하는 설계 원칙으로 적용한다. TypeSafe API 사용은 필수가 아니다. 공급자는 Sakana 공식 API로 준비하며 모델 교체가 지식/판단/검증 전체 재작성을 요구하지 않도록 한다.

## 구조 및 구현 현황

공개 원본 수집 → 출처·판본·확정 상태 검토 → 승인 지식 계약 → 질문 검사 → 필요한 지식 선택 → 서버 답변 조립 → 평가.

- 기존 knowledge.mjs의 출처 SHA·상태·답변을 재사용한다.
- decision-engine.mjs는 정확한 주제 버튼은 모델 없이 처리하고 자유 질문만 공급자에 위임한다. 개인정보 형태·직원 확인 범위 검사 선행. 자유 질문을 단순 키워드 일치만으로 단정하지 않는다.
- model-provider.mjs의 Sakana 어댑터는 공식 Chat Completions API와 구조화 출력을 사용한다. 요청은 최대 1회, 자동 재시도/도구 호출 없음. 모델 ID는 환경 설정으로 받는다.
- 모델은 최대 3개 안내 ID와 재질문 여부만 반환한다. 서버는 허용 ID, 중복, 개수, 응답 형태를 검증하고 확인된 답변만 조립한다. 모델이 임의로 만든 가격이나 문장은 고객에게 전달하지 않는다. 자기보고 confidence를 정답 확률로 사용하지 않는다.
- consult의 새 경로는 CONSULT_PROVIDER가 있을 때 선택한다. 이전 TypeSafe 경로는 회귀 비교용으로 남아 있으며 신규 공급자로 자동 우회하지 않는다.
- 외부 호출에는 서버가 주입한 externalAllowed=true가 별도로 필요하다. PR #33 통합으로 HTTP 핸들러가 공유 제한 저장소 검증 후에만 이 값을 주입한다. 저장소 미설정·오류 시 외부 호출은 차단된다. 실제 외부 연결은 미검증이다.
- 실제 API/배포/키 설정 미실행. 공급자 교체 계약의 합성 시험은 구현했다. 어떤 모델도 동일 품질을 보장하지 않으므로 실제 한국어 평가를 공급자별 수행한다.

## 서버 설정 — 비밀값은 채팅/저장소에 기록하지 않음

- CONSULT_PROVIDER=sakana
- CONSULT_MODEL=계정에서 확인한 모델 ID (기본 후보 fugu, 자동 지정하지 않음)
- CONSULT_ENABLED=false (최초 설정)
- SAKANA_API_KEY=서버 비밀 환경변수

공식 근거: https://console.sakana.ai/get-started , https://console.sakana.ai/models (2026-10-05 확인). Sakana의 출력 토큰 제한은 전체 내부 오케스트레이션 비용 상한과 같지 않다. 구독 포함 범위/과금 모드는 해당 키에서 별도 확인한다. 타사 모델 풀 사용 여부도 Sakana 계정 설정과 정책에 따른다.

## 데이터 수집 확장 — 아직 구현되지 않은 범위

원본을 무조건 모델에 넣지 않는다. 지식 수집기의 입력에는 출처 ID, 취득일, 원본 해시, 공개 범위, 유효기한을 요구하고 신규 자료는 검토 대기 상태로 둔다. 모델의 요약이 confirmed를 자동 부여하지 못하게 한다. 상담 중 외부 웹이나 내부 Drive를 무단 검색하지 않는다.

평가 데이터는 우선 합성 질문과 직원이 검토한 수정 사례를 사용한다. 고객 원문 자동 저장은 이번에 켜지 않는다. 추후 저장할 통계는 주제·지식 버전·공급자·지연·사용량·실패 사유를 중심으로 설계하고 개인정보/보존 정책을 먼저 정한다. 수집기·영속 통계 저장소·자유 생성 답변·실시간 예약 연동은 아직 구현되지 않았다.

## 담당 조정

벤은 이번 변경에서 consultation.mjs의 공급자 분기, 새 decision-engine.mjs/model-provider.mjs/provider.test.mjs를 소유한다. 기존 통합 브랜치에 반영한다.

아난티 ANT-004는 R2 수정과 함께 HTTP 핸들러/호출 제한을 JEV 전용에서 공급자 공통으로 확장한다. CONSULT_ENABLED와 기존 JEV_ENABLED를 명확히 구분하고 새 경로도 공유 제한 저장소 검증 후에만 externalAllowed를 서버 내부에서 전달한다. 요청 JSON에서 해당 허용값을 받지 않는다. 새 키만 넣었을 때/저장소 누락·고장·비정상 응답에서 외부 호출 0건 회귀 필수. UI의 모델 표시를 mode==='jev' 전용에서 mode==='model'도 지원하도록 조정하고 TypeSafe 전용 개인정보 안내를 실제 공급자 안내로 정정한다. 아직 실제 호출/배포는 하지 않는다.

클로이의 CLAUDE-009 완료 상태는 유지한다. 추가 지식 수집기·평가셋 구현은 벤의 별도 배정 후 착수한다. 지오는 기존 시험 URL 대기 상태를 유지한다.
