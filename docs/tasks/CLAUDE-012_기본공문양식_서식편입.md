## 1. 요청 내용

대표 요청으로 만든 기본 공문 양식을 운영시스템 서식 모음(`01_봉플레이_운영시스템/forms/`)에 넣어, 다른 서식처럼 화면에서 채우고 인쇄하거나 PDF로 저장하게 해 달라는 요청이다. 범위 확정, 담당 배정, 결정 사항 질문은 벤에게 넘긴다.

## 2. 양식이 만들어진 과정

1. 대표가 참고용으로 다른 시설의 공문 PDF(2026-10-28, 2쪽)를 제공했다. 이를 따라 1차 양식을 만들었다.
   - 반영한 요소: 머리 로고, 수신·경유·제목, 본문 번호 문단, "다음", 붙임 상세표, 하단 결재·시행 정보
2. 대표가 봉뜨락이 실제로 보낸 공문(2026-09-08, 봉화군 문화관광과 수신, 1쪽)을 주며 "이 골격 기반으로" 다시 정리하라고 했다. 이것이 최종본이다.
3. 로고는 대표 지시대로 BONG PLAY만 쓰고 RE:PLAYCE는 뺐다. 내용은 비워 두었다.

참고 원본 PDF 두 개는 실제 기관 간 공문이고 담당 공무원 이름이 들어 있어 저장소에 넣지 않았다. 아래에는 구조만 적는다.

## 4. 양식 구조 (서식으로 옮길 때 기준)

### 1쪽: 공문 본문 (A4 세로, 여백 상하 약 1.8cm, 좌우 2cm)

| 순서 | 블록 | 내용 | 고정 문구 / 입력 칸 |
|---|---|---|---|
| 1 | 머리 | 왼쪽에 BONG PLAY 로고, 가운데에 "리틀포레스트 봉뜨락"(굵게, 18pt) | 고정 |
| 2 | 수신 | `수신자 :` `(경유)` `제    목 :`(제목 굵게). 제목 아래 얇은 회색 선 | 각 항목 값이 입력 칸 |
| 3 | 본문 | 1·2·3 번호 문단 (내어쓰기) | 입력 칸. 안내 문구: 협조 감사 / 요청 배경과 요청 사항 / 검토·승인 요청 |
| 4 | 다음 | 가운데 정렬 "-  다  음  -" | 고정 |
| 5 | 세부 | `□ [요청 건명]` → `1. 주요내용` → `1) [세부 내용]` | □ 건명과 1) 항목이 입력 칸, 항목 추가 가능해야 함 |
| 6 | 붙임 | `□ 붙임 : [첨부 문서명] 1부.  끝.` | 첨부 문서명이 입력 칸 |
| 7 | 하단 (첫 쪽 바닥 고정) | 회색 띠 아래 세 줄: ① `기안 [이름]` … `[YYMMDD] 전결` ② `시행 리틀포레스트 봉뜨락` · `[직위] 홍성현` ③ `전화 010-5931-4144` · `이메일 bongplay@outlook.kr` · `/[공개 구분]` | 이름, 날짜, 직위, 공개 구분이 입력 칸. 나머지는 고정 |
| 8 | 쪽 번호 | 가운데 아래 | 고정 |

- 글꼴: 9/8 공문에 맞춰 본문은 명조 계열(docx는 바탕), 머리 제목·하단 정보·표 머리는 고딕(맑은 고딕).
- 색: 1쪽은 흑백 위주. 붙임 제목 띠만 브랜드 초록 `#0B4A2B`.

### 2쪽: 붙임 상세 (선택)

- 초록 띠 `Ⅰ [붙임 제목]`
- 표 `순서 | 항목 | 사진 | 내용` (너비 비율 약 9 : 17 : 25 : 45), 빈 행 4개
- 1차 참고 공문의 상세표 형식이며, 9/8 공문에는 없던 부분이다.

## 5. 서식 편입 제안 (구현 담당 배정 필요)

현재 서식 모음 구조를 따르면 아래처럼 넣을 수 있다. 코드는 아직 작성하지 않았다.

1. **새 파일:** `01_봉플레이_운영시스템/forms/official-letter.html` (가칭 "공문 (기본)").
   - 다른 서식과 같이 `form-style.css`, `form-script.js`를 쓴다.
   - 입력 칸은 `.f` 칸(`contenteditable`, `data-ph` 회색 안내)으로 만든다.
   - 위쪽에 "쓰는 법" 안내와 `인쇄 / PDF로 저장` 버튼을 둔다.
2. **목록 등록:** `forms/index.html`의 "군청 제출용" 그룹에 카드를 추가한다(운영실적보고서·시설변경신청서 옆). 설명 예: "군청·기관 발송 기본 공문. 수신·제목·본문·붙임".
3. **로고:** `01_봉플레이_운영시스템/assets/images/bongplay-logo.png`로 넣는다. 배포 ZIP 허용 목록은 이미 아래 패턴을 포함하므로 스크립트 수정은 필요 없어 보인다. 실제 ZIP 생성으로 확인해야 한다.
   - `build_deploy_zip.ps1` 40행 `^forms/[^/]+\.(html|css|js)$`
   - `build_deploy_zip.ps1` 42행 `^assets/images/...\.(png|...)$`
4. **하단 고정:** HTML 인쇄에서는 하단 정보를 첫 쪽 바닥에 고정하기 어렵다. 다음 중 하나를 고르면 된다.
   - 본문 영역을 A4 높이로 잡고 하단 블록을 아래로 밀기
   - 본문 바로 뒤에 두기
5. **붙임표:** 2쪽 표를 넣을지, 넣는다면 "행 추가" 버튼을 둘지 정해야 한다(D6).

### 제안 완료 조건

- [ ] 서식 목록에서 카드로 들어가 모든 입력 칸에 입력할 수 있다 (PC, 태블릿).
- [ ] 인쇄 미리보기에서 A4 1쪽 안에 머리부터 하단 정보까지 들어가고, 안 채운 칸은 기존 서식처럼 점선 빈칸으로 나온다.
- [ ] 붙임 페이지를 넣는 경우 2쪽으로 분리되어 인쇄된다.
- [ ] 다른 서식과 `form-style.css` 공통 스타일에 회귀가 없다.
- [ ] 배포 ZIP에 `forms/official-letter.html`과 로고가 포함된다.

## 7. 검증 결과와 미실행 항목

- 실행함: docx 생성 → LibreOffice로 PDF 변환 → 1·2쪽 화면 확인. 하단 정보가 한 줄씩 들어가고, 1쪽 본문과 2쪽 붙임표가 분리되는 것을 확인했다.
- 실행함: 배포 ZIP 허용 목록 패턴 대조(코드 읽기).
- **미실행:** Microsoft Word와 한컴오피스(한글)에서 열기. 이 작업 환경에 한글 글꼴(바탕·맑은 고딕)이 없어 Pretendard로 대체해 렌더링했다. 실제 줄바꿈과 쪽 넘김은 Windows에서 다시 확인해야 한다.
- **미실행:** HTML 서식 구현과 브라우저 인쇄 검증. 아직 구현 전이다.
- **미실행:** 배포 ZIP 실제 생성.

## 8. 남은 문제

- 서식 모음 전체의 상호 표기("봉플레이")와 공문 머리("봉뜨락")가 다르다. D1 결정에 따라 한쪽으로 맞추는 작업이 따로 필요할 수 있다.
- 사업자 형태(개인/법인)에 따라 "대표"/"대표이사"와 발신명의 표기를 서식 전체에서 통일해야 할 수 있다(D2).
