### 최소 완료 조건: 실제 브라우저에서 아래 세 시나리오

로컬 HTTP 서버, 별도 테스트 브라우저 프로필, 합성 config와 데이터, 네트워크 경계의 모의 서버/라우트 차단을 사용한다. 실제 제품 HTML/JS와 실제 버튼을 사용하고, 실행할 제품 함수를 테스트용 복제 함수로 대체하지 않는다. 외부 운영 URL로 쓰기/조회가 나가지 않게 차단한다. 두 뷰포트 390×844 및 1440×900에서 핵심 조작 요소가 가려지지 않는지 확인한다.

1. **안전점검→POS**: 당일 최신 부적합/이전 적합 합성 기록에서 결제 동작을 시도하면 주문/수납이 생성되지 않는다. 정상 재점검을 실제 화면에서 저장한 후 POS 갱신으로 발권할 수 있고, 같은 제출 연타로 주문이 중복되지 않는다. 관찰값은 합성 원장 건수와 화면 결과로 남긴다.
2. **입장→취소→퇴장 및 타 단말**: 합성 가족 1건을 실제 게이트 UI에서 입장시킨다. 취소 후 신규 입장은 막되 실제 퇴장 전 체류 인원을 유지하고 퇴장 UI가 동작해야 한다. 별도 브라우저 컨텍스트/독립 저장소의 B단말이 동일 모의 서버를 통해 취소를 수신한다. 서버 스키마 누락 시 성공으로 표시/큐 삭제하지 않고 원본 payload 유지, 스키마 복구 후 재전송 시 취소 상태 전달과 큐 해소를 검증한다. 단말 B의 결과를 테스트에서 미리 취소 상태로 주입한 것만으로 전파 성공이라 하지 않는다.
3. **마감 A→빈 B→A**: 합성 A일 확정 기록은 잠금 유지, B일로 이동하면 A의 매출·지출·권종·메모가 섞이지 않는다. 미저장 초안을 가진 날짜를 왕복하면 정의한 초안 정책대로 보존/복원된다. 실제 입력·날짜 변경과 저장 버튼의 결과를 검증한다.

### 증거와 실행 종료

- 각 시나리오에 입력/동작/기대값/실제값/통과 여부를 남기고 실패 시 단계·스크린샷·관련 콘솔 오류를 남긴다. DOM에 제목이 있다는 검사나 PNG 크기만으로 흐름 통과라 하지 않는다.
- 실행은 타임아웃과 단계 로그를 갖고, 끝나면 이번 실행에서 만든 서버/브라우저만 finally에서 종료한다. Windows 백그라운드 창은 windowsHide/Hidden 사용. 사용자 브라우저나 다른 프로세스를 종료하지 않는다.
- 브라우저 자동화 도구/권한이 막히면 반복 팝업 실행하지 말고 정확한 오류와 마지막 단계, 재현 명령을 보고한다. 미실행을 통과로 쓰지 않는다.
