# ANT-001 — 아난티: 운영시스템 전수검증 및 중대 결함 수정

배정: Ben / 담당: 아난티(Antigravity) / 배정일: 2026-09-29.

## 임무와 완료 상태

`01_봉플레이_운영시스템/`의 고객·직원 업무 흐름을 실제로 실행해 검증하고, 재현된 P0/P1 결함을 수정한다. 문서 분석만으로 완료하지 않는다. 실행 가능한 로컬/테스트 환경, 재현 증거, 의미 있는 회귀 테스트, 검토 가능한 PR까지 제출한다.

큰 작업은 단계별로 진행한다. P0는 운영 데이터 손상·타인 개인정보 노출·안전 제약 우회 등 즉시 사용 중단을 검토할 결함, P1은 발권·입퇴장·마감 등 주요 흐름을 막는 결함으로 분류한다. 심각도는 증거와 영향으로 설명한다.

## 착수 및 소유 범위

- 최신 `origin/master`에서 별도 checkout/worktree와 `antigravity/ANT-001-operations-integrity`를 만든다. 이전 보고의 `3830fad`를 고정 기준으로 쓰지 않는다. 실제 기준 SHA를 기록한다.
- `AGENTS.md`, 작업표, `BEN-002_이관결정과_면적근거.md`와 이 지시서를 읽는다.
- 수정 허용: `01_봉플레이_운영시스템/`의 HTML·JS·CSS·Service Worker, 해당 범위를 위한 새 테스트, `docs/qa/ANT-001_운영검증.md`, `docs/qa/evidence/ANT-001/`, 작업표의 ANT-001 행.
- 공통 JS는 **이번 운영 검증에서 재현된 결함 수정과 면적 의미 분리**에 필요한 범위에서 수정 가능하다. 대규모 모듈 재편이나 전면 디자인 교체는 별도 작업으로 제안한다.
- DB SQL·권한·백엔드·배포 설정은 읽고 검증하되 변경이 필요하면 재현 근거와 패치 제안을 보고서에 담는다. 현재 작업에 임의로 섞지 않는다. 운영 DB/배포에는 적용하지 않는다.
- `02_리플레이스_브랜드사이트/`는 이 작업에서 읽기만 가능하다. 후속 ANT-002에서 별도 수정한다.
- `04_봉뜨락_업무로그_AI/`와 과거 chatlog/netlify-site는 지오, `05_` 및 과거 agents 이관은 클로이 담당이다.
- 클로이의 기준정보 어댑터 설계와 충돌하지 않도록 기존 전역 객체·키와 공개 함수의 호환성을 유지하고, 수정한 계약은 보고한다.

## 1단계 — 환경과 전체 화면 조사

1. 실행에 필요한 설정을 조사하고 로컬 또는 격리된 테스트 환경을 구성한다. 운영 자격증명은 복사하지 않는다. 테스트 전용 설정은 커밋하지 않으며 필요한 예시만 남긴다.
2. 루트 포털, `pages/`의 14개 화면, `forms/`의 포털 및 서식을 실제로 열어 표를 만든다. 실제 파일 수가 바뀌었으면 발견한 목록을 기준으로 한다.
3. 각 화면의 로딩, 주요 링크, 필수 JS/CSS, 콘솔 오류, 인증 전후, 빈 데이터/오류 상태를 확인한다. 최소 390×844 및 1440×900 두 뷰포트로 확인한다.
4. CDN·설정·DB 의존성을 구분한다. 설정이 없는 상태의 제한을 서비스 결함과 혼동하지 않는다.
5. 코드상 경로, 브라우저 모의 응답 테스트, 실제 테스트 DB 결과, 운영 읽기 확인을 구분해 기록한다.

## 3단계 — 근거가 확정된 면적 표현 정리

### 추가 우선 과제: 운영시간 고객 고지 정정 (2026-09-29)

- 전달된 대표 결정은 운영시간 미정이다. `pages/booking.html`의 10:00~18:00·입장 마감 17:00 고지를 '운영시간 확정 후 안내'로 바꾸고 고객용 화면과 FAQ에 같은 미확정 시간이 재노출되는지 확인한다.
- 정기휴무도 별도 승인 근거가 없으면 확정 고지로 유지하지 않는다. UI·문구 수정은 이 작업에 승인된 범위다.
- 내부 계산에 쓰는 시간 상수를 임의 삭제하거나 null로 바꿔 동작을 깨뜨리지 않는다. 계획값과 고객 고지 상태를 구분하고 경계값을 테스트한다. 상세 근거는 `docs/migration/BEN-004_클로이_PR검토와_기준정보결정.md`를 따른다.

### 면적 표현

- 건물 연면적은 924㎡, 시설명세의 실내놀이시설장은 657.785㎡다. 상세 출처는 BEN-002를 따른다.
- `area_sqm`의 모든 사용처를 먼저 추적한다. 기존 필드 의미를 조용히 바꾸지 않고 건물 연면적과 놀이공간 면적을 구별하는 필드를 추가하거나 명확한 계약을 정한다. 호환성을 확인한다.
- `bongplay-id.js`, `bongplay-id-core.js`, `booking.html` 등의 표현을 용도에 맞춰 정리한다. 고객에게 놀이공간 전체가 924㎡인 것처럼 표시하지 않는다.
- 기존 단일 파일과 core 파일의 로드 경로를 비교하고 값이 갈라지지 않도록 검증한다.
- 면적과 무관한 요금·인력·안전 임계값은 변경하지 않는다. 현행 값이 코드에 있다는 이유만으로 법정/현장 확정값이라고 새로 표현하지 않는다.

## 4단계 — 수정과 회귀 검증

- 재현된 P0/P1을 원인 단위로 고친다. 실패 재현 → 수정 → 통과를 보여주는 테스트를 남긴다. 테스트를 통과시키려고 기대값만 바꾸지 않는다.
- 최소한 합계/중복 제출/게이트 중복 처리/마감 잠금/오프라인 재시도 중 실행 가능한 핵심 규칙을 의미 있게 검증한다. UI 테스트와 서버 보장 범위를 분리한다.
- 테스트 프레임워크가 없으면 하나만 최소 도입하고 실행 명령·버전을 기록한다. 별도 불필요한 앱 재구축은 하지 않는다.
- 모든 화면의 기본 동작을 다시 확인하고 수정과 관련된 핵심 흐름을 재실행한다. 인쇄 서식은 출력 미리보기에서 잘림과 빈 필드를 점검한다.
- 서로 무관한 수정이 커지면 원인별 후속 작업 ID와 분리 PR을 제안한다. 여러 에이전트가 같은 작업 공간을 공유하지 않는다.

## 후속 ANT-002 — 브랜드 접점 검증
